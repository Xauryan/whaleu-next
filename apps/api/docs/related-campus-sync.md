# Opt-in related-campus ordinary posts

A synchronized post remains one canonical post in its original space. Its author,
anonymous persona, discussion graph, reactions and counters are never copied.
The current accepted Campus topology determines which other regional spaces may
project it. Publication-time members are immutable audit evidence, not a frozen
audience. Removing a member withdraws that projection; adding a member includes
already-published eligible roots. Turning off the original school's setting or
withdrawing current applicability prevents new synchronized roots, while existing
roots retain their accepted publication shape.

## Explicit admission

`syncToRelatedCampuses: true` is opt-in and is the final conditional property in
the existing publication intent. False or omission retains the historical intent
bytes. Related roots use exact Review envelope version 4. Existing versions 1,
2 and 3, including old request recovery, retain their bytes.

Admission needs all independent current owners: the actor's selected physical
identity campus must map to the exact original operating region; the original
school setting must enable new sync; Campus must provide a complete accepted
multi-region group; accepted applicability must explicitly cover the category,
author mode, component, images and anonymous-DM choice. The ordinary schema
candidates are discussion, confession, companions, pets, internships, scenery,
dorms, research and deep_sea. Candidate names are not accepted policy.

No migration seeds topology, accepted applicability, Review acceptance,
relationships, grants or a provider. The nonproduction manual Review adapter has
a separate explicit `COMMUNITY_RELATED_REVIEW_POLICY_ID` and `local-related-v1`
domain. Production cannot infer approval from the legacy manual Review flag.

Every v4 root has one immutable native distribution binding. SQL independently
checks the exact command hash, current admission, Review decision, root/approval
creation transaction and completed native receipt. Every new comment/reply under
that root requires its own v4 inherited approval in its creation transaction.
The inherited reference contains only canonical root identity/decision/digest;
actor identity and affiliation fields are the child's own. A legacy v1 child
under a v4 root is rejected. Child admission does not reopen the original root's
current issuance head or setting; its own owners and current canonical root
Review visibility remain required.

## Discovery and completeness

Regional feed, hot and lexical search resolve one opaque transaction-owned view
scope. Candidate batching does not resolve topology per post. `space` remains the
original space; a proved remote projection has `isRelatedCampusSync: true` and a
safe original `sourceRegion` label. At the origin, the flag is false and the source
label is absent. Detail accepts an explicit `viewSpaceId`.

A regional page reports `relatedCampusDistribution: complete | unavailable`.
Unknown topology permits only an explicitly incomplete local page. An unknown
required row proof fails the page rather than silently certifying a complete
result. Cursors bind current scope facts. Regional semantic full-corpus search
and exact counts cannot turn unknown coverage into complete or zero. Broad,
global, own, profile, saved and liked selectors remain canonical and do not
acquire unrelated topology dependencies. Semantic embeddings remain keyed by
canonical content, so adding a related destination does not require duplication.

View handles cannot be reused after a transaction checkpoint restore. Required
selection completes before optional serialization; safe display values may then
be projected without reusing stale owner handles. Final source fences compare
the originally observed generations after waits, including zero-row source
statements. These generations are guarded monotone metadata, not count-capacity
owners.

## Scoped management

Pin command version 2 binds the viewed destination space. A and B have independent
slots. Existing original-space developer authority remains unchanged; a new
remote destination branch requires that destination's fixed school administrator
or a super administrator. Exact own-slot cleanup remains possible after a
projection is withdrawn, without granting new content authority.

Pure content-removal command version 3 binds `viewSpaceId` and carries no account
punishment. Compound punishment remains under direct-original/super authority;
the shared punishment grant helper is not expanded to related destinations.
Category reclassification, nickname and avatar moderation on synchronized targets
are explicitly unavailable in this slice before any mutation or private profile
projection. Existing none-target behavior and recovery remain unchanged.

Mute and suspension continue to use the existing account-policy owner. Mute
restricts interaction and content management; suspension retains only the
established restricted self-service/recovery paths.

## Compatibility and validation

Optional constructor seams exist only for historical isolated unit ports. Missing
owners never authorize sync or certify complete regional/semantic coverage.
Real AppModule integration fixtures assert that every actual consumer receives
the same distribution owner. Historical migration-prefix applications use an
explicit test-only adapter and exact checksum/absent-object proof; production has
no missing-table fallback.

The applied SQL golden inventory contains all 139 pre-feature files: 137 primary
migrations through 0137 and two optional semantic migrations. The feature adds
0138 (core), 0139 (publication/settings) and 0140 (scoped management), without
rewriting an applied migration. Related suites cover canonical/hash contracts,
raw SQL attacks and old-prefix replay, discovery, settings, scoped management,
optional semantic completeness, and emitted native Page/WXML through real HTTP
AppModule and PostgreSQL. The modular integration inventory registers each new
regular PostgreSQL file; the optional semantic runner includes its own directory.

### Static compiler resources

The API `typecheck` command gives only its TypeScript process a 3072 MiB old-space
heap. It retains the complete existing `tsconfig.json` file set; no source or test
is excluded. There is no global `NODE_OPTIONS` and no runtime, unit, PostgreSQL,
proof deadline, count budget or build-process heap change. On the pinned two-CPU
local comparison, baseline 77 checked 2764 files with 2,579,661 instantiations and
candidate checked 2785 files with 2,624,132 instantiations (about 1.7% growth).
The baseline already approached the local default heap; the candidate exhausted
it. Failed default-heap logs are retained as resource evidence. This explicit
compiler setting is an engineering-scale accommodation, not a claimed runtime
performance fix.
