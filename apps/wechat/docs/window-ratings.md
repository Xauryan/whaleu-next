# W1 specialist window ratings

The Ratings catalog, scoped entry and recovery entry link to the native window directory. `window-ratings` and `window-rating-detail` are registered pages using the App runtime, strict specialist gateway and the existing account/login-generation lifecycle fences.

Only the accepted source catalog supplies canteen and floor selectors. Canteens support bounded multiple selection; floor IDs and raw floor keys remain opaque. The minimum-rating control follows the accepted legacy rule: only a positive value enables filtering; zero and negative values leave negative candidates visible. Pages replace bounded result slices and invalidate continuation when the catalog or score epoch changes.

All 21 integer scores from -10 through +10 are explicit choices. Zero is a rating, absence is distinct, and unavailable history never becomes zero or a new-score entitlement. A current score is editable; every change requires a fresh explicit preview and confirmation. The request captures the catalog, window and nullable prior own-score revisions. A stale own revision requires a new decision after refreshing rather than silently overwriting another edit.

Before first transport the account/origin-scoped journal persists and reads back the original request identity, operation, target, signed score and expected revisions. Recovery reads the original receipt before any exact retry. Cancellation is a separate explicit decision; its phase is persisted before dispatch so a restart cannot retry the score after cancellation was chosen. A receipt miss, hide/back, transport error or snapshot read never releases the journal. Only a matching terminal receipt does. Historical applied/noop receipts never constrain or replace the current detail: current data is independently re-read and may be newer or unavailable.

Coverage includes strict DTO/transport tests, controller state/recovery/lifecycle tests and an emitted App/Page/WXML worker crossing real loopback HTTP into AppModule/PostgreSQL. Synthetic platform storage, navigation and transport interruption are the only client substitutes; the fixture supplies explicit synthetic source acceptance and independent history coverage. This does not establish real source acceptance, real provider, WeChat DevTools or physical-device acceptance. Production source remains unavailable by default. The separate [W2 dish contract](../../../docs/DISH_RECOMMENDATIONS.md) now adds exact-native endorsements through a linked route. W1 itself includes no comments, floor scores, images, reward or notice workflow.
