# Native component and business-flow coverage

Audit: 2026-10-20. Source of truth: [`apps/wechat/src/app.json`](../apps/wechat/src/app.json). Machine-readable inventory: [`native-component-flow-coverage.json`](../apps/wechat/docs/native-component-flow-coverage.json).

## What this inventory proves

Every one of the 120 registered routes has its own migration decision, source files, required business flow, existing test references, and remaining real-dependency/acceptance gates. The focused inventory test rejects missing, extra, duplicate or substituted rows, stale component registrations through literal local template dependencies, unsupported exemptions and unsupported verification claims. It does not execute the indexed business suites or prove feature parity.

Current route decisions: **117 implemented**, **0 migration-needed**, **3 current-layout exceptions**, **0 fully verified**. The original 117 presentation routes plus three new manual-timetable routes are tracked individually. These counts describe this audited source snapshot, not a permanent execution result.

## Status and scope rules

- **migration-needed**: a page presentation exists, but its native Framework7 transcription is not complete. `inProgress` records active work without anticipating its outcome.
- **implemented**: actual local native components are adopted and focused source/action evidence exists. Remaining native controls may be deliberate exceptions or later work. This does not imply all business flows passed.
- **not-applicable**: only the current layout-replacement batch is excluded for accepted Home (`community-feed`), Messages (`inbox`) and Me (`me`). Their layouts/global tokens remain frozen. This is not permanent exemption from separately reviewed reusable-component work, business tests or device validation.
- **verified**: reserved for a source-bound route acceptance packet with native-unit, package, physical-device and, where applicable, actual emitted-Page/PostgreSQL evidence. No route has that claim here. Even such route evidence would not by itself establish real-provider or production readiness.

The initial four ports are `campus-tools`, `directory-hub`, `directory-list` and `browsing-history`. They retain native routing and business owners. Campus-tools and directory-list still contain direct native inputs; history retains its explicit native destructive clear-confirmation button. No cosmetic conversion may bypass permission, current-owner, storage, cancellation or uncertain-request recovery guards.

The next four source migrations are now implemented: community-search (block/button/searchbar), settings (block/list/button/toggle), directory-detail (block/list/list-item/button), and school-services (block/list-item/button). Their focused action-parity evidence is framework7-forms-migration.test.ts; Page TypeScript and intentionally native date picker/navigators remain unchanged. Aggregate package and device gates are still separate.

## Evidence is not interchangeable

1. Native Node unit/controller tests use test doubles and/or source assertions. They establish their bounded assertions, not Tencent rendering.
2. Expanded HTML/WXML previews and emitted template smokes are static/model evidence. They do not reproduce native style isolation, keyboard/focus, permission prompts, events or device accessibility.
3. `api-postgresql` checks real database/API owners with synthetic facts. It has no implied native Page journey.
4. `native-client-postgresql` adds actual native controllers/gateways/journals, sometimes a separate client process. A file named “native-roundtrip” is not automatically an emitted Page/WXML test.
5. `emitted-page-postgresql` executes actual emitted App/Page/WXML handlers against ordinary loopback owners and PostgreSQL. The WeChat platform and external providers remain synthetic. It is still not physical-device, real-provider or production acceptance.
6. `mixed-native-client-and-emitted-source-postgresql` records mixed bounded evidence without upgrading it to a full emitted interaction journey.

For example, directory, base ratings, activity-read, announcement-read, school-configuration and school-QR “native-roundtrip” files currently test the native client against PostgreSQL. They are explicitly classified that way in the JSON. Campus-tools has a distinct emitted-Page/PostgreSQL journey. The school-UID emitted smoke is only a branch/nullability proof; its lookup Page still needs a dedicated interaction journey.

The source-bound [focused PostgreSQL observation](POSTGRES_FOCUSED_VALIDATION.json) applies only to its named following/profile-details/profile-cover-media/owner-publications tests and recorded input hashes. Read that report for its actual outcome. This inventory does not cache its pass count, turn it into a full-suite result, or retain a transient failure as a permanent blocker. Broader PostgreSQL progress must be reported from its own completed run evidence.

## Required behavior in every applicable flow

- Eligible read/write path; denied, unavailable, unknown and known-empty must remain distinct.
- Repeated taps, deferred/out-of-order callbacks, replacement navigation and retry without duplicate mutation.
- Cancel, Back, Close, hide/show/unload and account/session switch, including observer suppression and stale private-state removal.
- For mutations: persistence failure before dispatch, lost response, frozen original payload/key, explicit recovery/cancellation and final current-authority checks.
- Preserve each owner’s permission, receipt namespace, cursor/pagination and media lifetime. A shared family test is relevant evidence, not a statement that all of a route’s scenarios ran.

## Real-dependency and acceptance gates

These are separate gates, not interchangeable test stages. “Evidence required” is not a claim that an installed dependency is absent. In particular, supported PostgreSQL availability and a bounded real run do not prove every integration file. Some provider/configuration gates apply only when that capability is enabled; the truthful unavailable behavior remains required now.

| Gate                                                       | Current boundary                                                                                                                                                                                                                                                                        |
| ---------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `native-device` (evidence-required)                        | WeChat DevTools and physical iOS/Android evidence for actual native style isolation, slots/events, focus/keyboard, accessibility, scroll/press cancellation, dark mode, safe areas and lifecycle. HTML previews, Node mocks and PostgreSQL do not satisfy this gate.                    |
| `pg-evidence` (evidence-required)                          | Run the relevant exact test files against disposable supported PostgreSQL and current emitted sources; preserve command, source identity, passed/failed/skipped/cancelled counts and failures. PostgreSQL 18.6 availability is not a suite result; no transient outcome is frozen here. |
| `wechat-provider` (external-validation-required)           | Authorized real WeChat AppID/domain/login/phone eligibility and privacy/consent/provider behavior. Synthetic identity/phone responses are not real-provider acceptance.                                                                                                                 |
| `review-provider` (external-validation-required)           | Configured trusted review issuance/processing and exact content proofs for the specific business owner. Controlled synthetic review cannot authorize production publication.                                                                                                            |
| `media-provider` (external-validation-required)            | Configured authorized Media/COS delivery/upload and review for the relevant owner, with real-device file lifecycle. Synthetic bytes/provider transport are not live media acceptance.                                                                                                   |
| `trusted-authority` (configuration-required)               | Current legitimately issued role/school/owner grants, revisions and eligible authority; fixture grants do not establish real operator enrollment or authority.                                                                                                                          |
| `trusted-catalog` (configuration-required)                 | Accepted current campus/domain catalog, provenance and validity. Synthetic seeds do not prove nonempty historical import, real data or production configuration.                                                                                                                        |
| `semantic-provider` (external-validation-required)         | Semantic search model/provider configuration and separately run semantic integration/evaluation; keyword tests do not validate semantic availability or quality.                                                                                                                        |
| `institutional-provider` (external-validation-required)    | Approved institution adapter, real SSO consent/callback configuration and continuity/expiry validation; missing adapter stays unavailable.                                                                                                                                              |
| `official-account-provider` (external-validation-required) | Authorized real official-account callback/token/notification capabilities and provider quotas; local operator simulations are not live delivery.                                                                                                                                        |
| `creator-crosswalk` (blocked-by-missing-dependency)        | Accepted window creator crosswalk is absent for creator-notice compatibility. Keep that capability unavailable; local notices do not prove imported creator delivery.                                                                                                                   |
| `wallet-provider` (blocked-by-missing-dependency)          | No financial-account/payment provider is implemented. The unavailable-state test verifies absence of invented money features, not a financial flow.                                                                                                                                     |
| `location-consent` (external-validation-required)          | Real-device native location consent, deny/cancel behavior and adapter availability; map browsing must remain usable without consent.                                                                                                                                                    |
| `embed-domain` (configuration-required)                    | Trusted injected embed attestation plus WeChat-registered business domain and native web-view behavior. Do not port external web content into F7 or enable arbitrary URLs.                                                                                                              |

Window creator notices and Major notices must not share an invented blocker: [Window](WINDOW_DISCUSSION.md) has an unavailable legacy creator mapping, while [Major](MAJOR_DISCUSSION.md) has no creator concept. Wallet has no implemented financial provider at all; its negative test proves the truthful unavailable state, not payment functionality.

## Deterministic inventory check

From the repository root:

```sh
node --import tsx --test apps/wechat/test/native-component-flow-coverage.test.ts
```

This is also discovered by the existing WeChat `test/*.test.ts` command. It has no network/database/provider side effects and does not rebuild or edit native source. Validation includes:

- Exact ordered equality with all 120 app.json registrations, uniqueness and all four page source files.
- Valid family/gate/test references and exact directly used F7 tags/native-control kinds versus current WXML/config.
- Source/test-backed component implementations, bounded accepted-layout exceptions and no fabricated migration status.
- Explicit API/client/emitted PostgreSQL layer distinctions, plus unavailable wallet/map/embed/Window-specific gates.
- Negative cases for missing/extra/duplicate/substituted rows, nonexistent tests, fabricated completion and treating mock/static/PG evidence as device proof.

## Updating this matrix safely

When a route actually migrates, inspect its final WXML/JSON and focused action-parity evidence, update only that row’s component/control list and migration state, and rerun the inventory check plus the affected suites. Do not update an in-progress row merely because component source exists. Keep accepted layouts untouched. Record external runs in source-bound result artifacts, link the exact applicable tests, and retain failed/skipped/cancelled/not-run distinctions. Do not mass-promote all routes from a package pass or an aggregate test count.

No commit, push, production deployment, live provider activation or full-project completion is asserted by this audit.
