# Rating category-link group promotion

This owner is a synthetic, source-backed replacement for the legacy operational
`ratingPush` entry. It is not an official-account draft/publication feature, a
human-adopted rating description/card generator, an Errand authority extension,
or a ranked rating feed. It adds no heat formula or native send menu.

## Ownership

- `notifications/rating-group`: purpose-specific effects, immutable attempts and

- Identity's originating-session facade, Campus's bounded all-of school-scope

## Safe default and activation boundary

Ordinary `AppModule` installs `RATING_GROUP_PROMOTION_RUNTIME=null`. No environment
switch, cron, startup enrollment, network provider, credential, real model,
billable shortlink allocator, production transport or real trigger is shipped.
The internal fixture scheduler accepts only an explicit UTC anchor/period and
service lineage. It does not imply that legacy code established a daily cadence.

Live activation still needs accepted current category/locator mapping, all scope
and default/test export permissions, exact platform receiver identities/consent,
transport/mini-program ownership and terms, secure credentials, qualified receipt
and retry semantics, monetary pricing/ceilings, renderer or required-shortlink
viability, scale/rate/cooldown policy, restore procedure and physical WeChat
acceptance. Synthetic microcredits have zero monetary spending authority.

## Original-key recovery

A persisted canonical command backs an opaque intent ticket. The operator's
minimal journal contains no token, payload, receiver secret or command body.
Recorded exact-hash replay returns metadata before new-admission expiry/source
checks. Unrecorded stale previews fail without a replacement key. Durable seal
and admission serialize on the same intent row, including a delayed old POST.
Payload inspection is a separate current-authority transaction.

Unknown generation, shortlink allocation and delivery remain independent.
Cancellation suppresses future work and does not recall accepted messages or
refund possibly consumed quota. Late evidence settles only the original exact
attempt. A confirmed delivery does not resolve an unknown optional generation.

## Synthetic acceptance and restore

Async preparation durably reserves one bounded effect cell under an exclusive
lock. The synchronous boundary consumes a private process-local permit, fixes
one immutable acceptance tuple and queues authentication plus metadata persistence.
No serialization, signing, filesystem or network I/O runs in that synchronous
boundary. Signing uses only the already fixed tuple; failure remains unknown. A disposable receipt subscription discloses the outcome after the
receipt is durable; timeout removes callbacks, not acceptance. A crash before
receipt persistence leaves unknown and does not establish nonacceptance.

The worker freezes a private permit capsule inside its final transaction. The
shared wrapper stamps the completed proof only after every owner validation and
exact deadline check, immediately before COMMIT. Successful COMMIT releases that
original instant; its latency consumes the same 100 ms window. Rollback, failed
proofs, copied capsules and reused transaction stamps cannot issue a permit. No
serialization or asynchronous preparation occurs between COMMIT and dispatch.

Each cell contains at most the stage's bounded dispatch history. No whole-history
scan occurs in prepare/dispatch/reconcile. The private fixture store and SQL
ledger have an explicit incarnation/restore-epoch binding. A new store or ledger
cannot silently replace the other. Stale preparation locks are not stolen;
coordinated restoration or incident investigation is required. Test diagnostic
receipt counting is not a production selection or dispatch primitive.

Local worker capacity is separate from durable receiver exclusion. Unknown
releases local capacity while retaining its receiver gate and quota. The shared
worker leases cap concurrent drains at four; expiring a worker/slot lease cannot
grant a resend. Final proof/dispatch starts only with seven seconds remaining;
receipt wait is at most five seconds inside the ten-second drain and lease guard.

### Category owner sources

Operational export accepts the Ratings owner's current `native` or
`compat_effective` lineage only after its existing category/ancestry/source/Review
qualification. `compat_effective` is the canonical scoped publication projection,
not a requirement for a legacy import: migration 0065 materializes current scoped
base/system-registry results into it. Fresh course/canteen fixtures use the real category-management HTTP flow with
accepted current system-registry sources, Review, publication and activation.
They do not inject a system category through a generic scoped issuer.
The independent purpose export policy and exact source revision remain mandatory.
Opaque legacy visibility is explicitly rejected. The current older `native`
category owner only admits general categories and cannot by itself manufacture a
system course/canteen category; the promotion layer does not bypass that rule.
Native scoped creation/current system-registry projection must continue through
the owning source facade; no historical source-kind whitelist is an export grant.
Representative fresh course and canteen success and opaque-source rejection remain
required in PG acceptance; source-only checks are not that evidence.

The isolated synthetic generation profile uses a conservative byte tokenizer:
input at most 512 UTF-8 bytes and output at most 128 UTF-8 bytes. A differently
tightened token profile fails closed until its own adapter qualification exists;
it cannot silently borrow the larger defaults. Optional output is delivered to
the bounded live subscription only. Durable synthetic receipts retain a separately
authenticated metadata tuple without output; restart recovery cannot regenerate
or rehydrate it. Qualified deterministic/native fallback remains available.
