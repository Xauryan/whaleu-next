`category_icon_epoch` cannot be deleted, truncated, reinserted or reset. Each update must preserve singleton/version and advance by exactly one. There is no mutable “already validated” flag or persisted byte-count cache.

At deferred execution, an epoch event whose value is older than the current epoch is skipped. The last event validates:

1. The union of this transaction's v5 outcomes and v5 `category_execution` causes. The union does not require an already valid receipt or outcome. `verify_category_icon_command` rejects missing or mismatched counterparts, validates the original strict text-plan projection, outer hash, source vector, exact Review coverage, receipt and same-release cause. `category_icon_final_roots` then requires the complete after-root set and every new appearance.
2. Every marked Category-icon release created by this transaction. `verify_category_icon_release` rechecks the complete same-release manifest, public and management coverage, current original sources, Review8, Media8, capabilities, all affected domains and combined 64 MiB admission.

A raw receipt with no outcome/cause is still rejected by its own deferred reverse boundary even if it contributes no command to that union. A legitimate unresolved null claim is not an applied or closed receipt. Cold cancellation uses the original exact actor/key/hash fence and cannot conceal artifacts or claim physical deletion.

`SET CONSTRAINTS` may run the current generation early, but every later relevant statement queues a new event. Savepoint rollback restores both facts and their queued events; a later writer must queue its own generation. The immutable manifest reverse hook checks the exact current-transaction original release, marker, digest and full immutable payload. It does not call the old whole-ledger verifier a second time: that unchanged verifier remains attached to the original release. A manifest cannot borrow a previously committed release's old validation.

## Deletion and missing counterparts

- Original `rating_request_immutable` rejects DELETE, receipt replacement and transitions back to null before data disappears.
- C1 immutable artifacts reject UPDATE/DELETE and retain against TRUNCATE. Original source, release, outcome and cause retention guards remain.
- The legal mutable exception, `category_icon_definition_heads`, resolves DELETE from OLD's exact root key and definition in the unique current execution's before/after plan. Its BEFORE STATEMENT epoch event still queues complete closure validation.
- Management Review pointer deletion is rejected; permitted pointer updates retain exact identity and must prove the current root/source/Review/release.
- Physical hold closure is independent and cannot erase publication or cleanup evidence.

## Original target and Media co-writes

An adopted original target execution begins its Category collector before its own Category qualification. The capability binds its transaction/savepoint epoch, actor, request, original intent hash, create/edit operation and complete original campus-proof scope set. Only the matching same-transaction original create execution and preparation may consume one foreign publication. A second publisher, changed cause/scope, stale capability or missing finish fails closed. The original execution seals the post-write head/manifest/epoch fingerprint after its outcome and retained original scope; the complete same-release C1 SQL verifier independently rechecks the carried root/Review/Media closure. No earlier independent read proof is removed or converted into a mutation fact.

Category8 Media facts can also be newly collected by an already-owned Ratings Media mutation. Their exact ordered snapshot expectations join the existing cover/discussion obligations within the unchanged total 256-reference limit. Finish re-reads all exact typed facts after owned writes; the final epoch fence additionally locks Category8 markers only when Category8 obligations exist. Existing independently enrolled Media reads remain and still reject an own-write epoch change. Adopted v3 target execution opts in before reading its Category; v4 uses its existing mutation. Cover write transport uses the same owner wrapper, while read-only transport keeps its independent proof. No Category8 query is introduced for a collector with only historical cover/discussion references.

## Source-only discovery after consolidation

There are two independent live-reference sets:

- Public/compat authority: every current `scoped_catalog_heads` lineage and every current `compat_heads.scoped_tuples` lineage, with no affected-scope or adoption filter.
- Recoverable management authority: current stored base/override definition heads, including dormant, removed-campus and archived roots.

Only when neither set references an exact source may `category_icon_source_consolidated` exclude it from source-only discovery. Exclusion additionally requires immutable same-identity predecessor/successor definitions, a v5 scope-consolidation before/after plan, the sole outer hash and internal text hash, exact original execution/publication causes and same-release manifest. Historical use requires the original applied receipt; in-flight use is limited to the current constrained execution transaction. Rollback removes that proof together with its facts.

The first current-lineage branch of `category_icon_complete_roots` is never filtered by this exclusion. The original source head and all historical metadata remain intact. A frozen native catalog unsupported by current divergent compatibility is not itself current image authority; it neither permits historical downloads nor pins an otherwise precisely consumed source forever.
