## Recovery and terminal cleanup

Native recovery asks for the original business receipt first. Unknown or cancelled uploads keep the original actor/key/hash obligation; no automatic new key or false erasure. The shared local limits remain 2 I/O, 4 leases and 10 MiB, with 32 icons handled in bounded batches. The server's 64 delivery credits/2 per actor and the 64 MiB Ratings metadata/64 KiB HTTP command limits are separate budgets. The original shared Media 10 uploads/minute and 100/day limits also remain unchanged. A 32-image acceptance command waits through three real minute windows while retaining one original context, text projection and upload keys; the focused run completed in 211.9 seconds within the fixed maximum five-minute context. Upload scopes never outlive that context or the original text plan. Rate-limited native work offers continuation of the original journal; expiry requires explicit closure/recovery before a new draft, not silent key replacement or renewal.

An applied command that displaces an appearance creates a durable retirement queue entry. Keep, inherited references, dormant overrides and archive/restore do not detach it. Retirement requires an exact empty recoverable closure and no valid prepared-command, unresolved-root, open delivery, active worker or unknown-retention hold. Scope obligations survive removal and are checked against current original management authority. Successful upload leaves an exact never-claimed scratch cleanup obligation; requiring its deletion while the binding is live would deadlock the terminal-only collector. Admission therefore recognizes only the original scratch effect/reason/locator, retired writer, pending state, zero attempts and no lease. Final validation additionally recognizes the exact original staged source/derived/variant cleanup shapes. Prior attempts, retryable/retained/deleting state, attempted cancelled jobs, unknown writers and even expired physical leases remain holds. No clock or lease clearance proves physical quiet; the original cleanup not-before delays and final NOWAIT table fences remain in force.

Delivery holds bind the authenticated request, purpose, context, qualification and exact server plan. They close only after the actual provider/setup/source/output lifecycle is physically quiet. A deadline, abort request or failed closure write is not proof of quiet and cannot expire the hold.

`POST /v5/ratings/category-management/retirement/status` accepts an original applied request ID, optionally narrowed to exact appearance IDs. It reveals only that actor's bounded retirement metadata after current all-of checks. `retirement/cleanup` explicitly retires eligible IDs and returns `cleanup_pending`, never a claim of physical deletion. Native shows the original receipt even if this independent status is unavailable, supports request-ID cold recovery, and requires an explicit per-image cleanup action. Journal 13 bytes are unchanged.
